# 开发、测试与提交约定

## 环境

- Bun 1.3+，本次在 Bun 1.3.14 下验证。
- 开发服务器由 `server.ts` 通过 Bun HTML 入口提供，不需要额外打包服务器。
- TypeScript 检查范围为 `src/**/*.ts`；测试由 Bun 和 Playwright 执行。

```bash
bun install
bun run dev
# 或 PORT=3001 bun run dev
```

生产构建：

```bash
bun run build
```

该命令重新生成 `dist/`，并复制 `THIRD_PARTY_NOTICES.md`；发布时保留第三方许可。perfect-freehand 由 Bun 打包，成品不请求 CDN。部署整个目录，而不是直接在浏览器中打开包含 TypeScript 引用的 `src/index.html`。`dist/` 和 `node_modules/` 不提交。

## 自动化检查

```bash
bun run typecheck
bun test
bun run build
bunx playwright install chromium  # 首次运行浏览器回归时安装
bun run test:e2e
```

`test:e2e` 自动选择空闲端口、启动开发服务，并在结束时关闭服务和浏览器。测试依赖为 Playwright 和 `@axe-core/playwright`，不会进入生产构建。

可选配置：

```bash
# 使用指定 Chromium 可执行文件
CHROMIUM_PATH=/path/to/chromium bun run test:e2e

# 保存 320 / 768 / 1024 / 1440px 布局截图到仓库外
SCREENSHOT_DIR=/tmp/web-drawing-review bun run test:e2e
```

### 测试职责

| 文件 | 覆盖范围 |
| --- | --- |
| `tests/geometry.test.ts` | 反向框选、最小尺寸、越界、命中、局部坐标和单点路径 |
| `tests/document.test.ts` | 区域身份、独立笔画、图层命中、重排、命名、删除、快照隔离和历史上限 |
| `tests/render.test.ts` | 独立裁剪、橡皮时间顺序、预览不落盘、导出契约和内容转义 |
| `tests/brushes.test.ts` | 预设、参数校验、压力来源、矩形扫掠、滤镜、旧笔画和版本 2 导出 |
| `tests/browser.ts` | 实际指针/键盘交互、取消草稿、导出事件、像素采样、响应式和 axe 扫描 |
| `tests/brush-browser.ts` | 浏览器辅助回归：七种笔触、独立设置、合成笔压力、纹理/柔边/透明度像素和无外部资源导出 |

像素回归会检查框外保持白色、上层擦空显露下层、后画笔画不被旧橡皮擦掉，避免仅检查 SVG 字符串却遗漏真实渲染问题。采样位置应避开抗锯齿边缘。

axe 回归扫描 WCAG 2 A/AA 和 2.1 AA 标签。自动扫描不等价于完整无障碍认证，仍需人工复核键盘焦点、读屏表达和真实触屏体验。

## 人工回归清单

### 基础编辑

- 空画布切到画笔/橡皮，不能留下背景笔画。
- 框选后自动进入画笔；反向拖动和画布边缘框选正确。
- 在当前框内画粗线并拖出框，整支笔刷不越界。
- 从框外按下再拖入，不产生笔画。
- 切换工具、Esc、取消指针、失焦均不保存草稿。

### 笔刷专项

- 四种画笔和三种橡皮外观不同，预设参数相互独立，画笔与橡皮大小不再联动。
- 荧光笔同一次起笔折返不重复加深，多次起笔可叠色。
- 柔边橡皮过渡渐变，低强度擦除可重复减淡，但不影响其他框。
- 用真实数位板/笔实测压力，确认低压力、高压力、抬笔、失焦和取消均合理；自动化笔事件不能代替设备测试。
- 光标不进入导出；铅笔与柔边导出后无需联网加载纹理/算法。

### 重叠和撤销

- 创建两个重叠框，确认新框在上、列表上层在前。
- 画布选择命中上层框，左侧能选择被遮挡框。
- 改变层级不移动笔画，也不改变区域 ID。
- 擦除上层内容后显露下层，而非出现白色覆盖。
- 重命名、重排、绘画、擦除、删除均可撤销/重做。

### 导出和布局

- 独立打开导出 HTML，视觉与已提交内容一致。
- HTML/SVG 没有编辑边框、名称标签或临时草稿。
- 空白透明框也能通过点击/键盘产生对应 ID 的区域事件。
- 320、768、1024、1440px 无横向溢出；小屏可以展开侧栏并用表单创建。
- Tab 焦点可见，控件有中文名称；名称输入不抢占文本删除和撤销。
- 含 `<`、`&`、引号或脚本结束标签的名称不会形成 HTML 元素或脚本。

## 修改边界

- 模型、交互、渲染、导出各自保持独立，新增工具不得绕过区域限制。
- 修改功能时同步更新相应测试和文档；规划能力不要写成已交付功能。
- 不提交 `dist/`、浏览器下载文件、截图或本机路径配置。
- 动手前查看 `git status`，保留用户已有改动，不使用 `git add .` 混入无关文件。

## 中文 Git 提交

每完成一批逻辑完整且通过检查的修改，创建中文描述的 Git 提交。建议格式：

```text
feat: 改为区域框选绘画并支持图层叠加
fix: 修复跨区域橡皮擦除问题
docs: 重写使用说明并补充路线图与绑定参考
```

提交前：

```bash
git status --short
git diff --check
git add <本批明确修改的文件>
git diff --cached --stat
git diff --cached --check
git commit -m "类型: 中文修改摘要"
```

文档变更与功能变更可分成不同提交。若工作区原本包含迁移或删除，只有明确属于本批任务的内容才进入提交；其余保持原状，不清理、不覆盖。
